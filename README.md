# منصة كود لاب التعليمية

تطبيق عربي RTL بـ React/TypeScript وFluent UI v9، مستضاف على Vercel مع وظائف Node.js/TypeScript serverless. Firebase Authentication للهوية، وCloud Firestore مصدر البيانات الدائمة، وFirebase Storage للملفات. لا يستخدم التطبيق MySQL أو Cloud SQL أو Cloud Run أو Firebase Hosting.

## تشغيل محلي

1. انسخ `services/web/.env.example` إلى `services/web/.env` وأدخل إعدادات تطبيق Firebase Web.
2. انسخ `.env.example` إلى `.env.local` (جذر المشروع) وأدخل اعتماد Firebase Admin كـ JSON في `FIREBASE_SERVICE_ACCOUNT_JSON`، و`FIREBASE_STORAGE_BUCKET`. لا تضع ملف/مفتاح الخدمة في المستودع.
3. أعد استخدام مشروع Firebase تجريبي/تطويري منفصل، وفعّل Authentication (Email/Password) وFirestore وStorage. طبّق `firestore.rules`, `firestore.indexes.json`, و`storage.rules`.
4. ثبّت الحزم من الجذر: `npm.cmd install`.
5. شغّل `npm.cmd run dev:api` عبر Vercel CLI؛ يقدّم Vercel الواجهة ووظائف `/api/*` معاً. إعداد Firebase Admin مطلوب للمسارات الخادمية. `npm.cmd run dev:web` وحده يشغّل واجهة Vite فقط، ولا يوفر API.

## إعدادات Vercel وFirebase

- اجعل جذر مشروع Vercel هو جذر المستودع، والأمر `npm run build:web`، ومجلد المخرجات `services/web/dist`. وظائف `api/[...route].ts` تُنشر كـ Vercel Functions.
- أضف متغيرات `VITE_FIREBASE_*` إلى بيئات Vercel للواجهة، و`FIREBASE_SERVICE_ACCOUNT_JSON` و`FIREBASE_STORAGE_BUCKET` إلى بيئة الوظائف الخادمية فقط. احتفظ بالاعتماد كقيمة سرية، ولا تبدأ اسمه بـ `VITE_`.
- إعداد Firebase Admin يعتمد بيانات حساب خدمة بصيغة JSON عبر بيئة Vercel. أنشئ حساب خدمة بأقل صلاحيات Firestore/Storage المطلوبة، ودوّر المفتاح عند الحاجة. لا تُنشأ الموارد أو الأدوار الافتراضية تلقائياً.
- أنشئ الحساب الإداري/المعلم عبر Firebase Authentication ثم امنح الدور بواسطة عملية خادمية موثوقة بعد تهيئة النظام. لا توجد كلمات مرور أو حسابات افتراضية داخل التطبيق. التسجيل العام لا يمنح أدوار المعلم/الإدارة/الإشراف.
- يسمح التطبيق بطلبات الدفع اليدوية فقط ولا يعالج بطاقات أو تحويلات. تفاصيل الدفع الفعلية تُدخل لاحقاً من لوحة الإدارة؛ لا توجد بيانات دفع مضمّنة.
- أقسام المتفوقين لا تعرض أسماء إلا بموافقة صريحة قابلة للسحب. الملفات الخاصة وإثباتات الدفع ترفع ضمن مسارات مقيدة، وتُتاح للمعلم/الإدارة عبر رابط موقّع قصير العمر عند المراجعة.

## حدود التكاليف والتشغيل

الخطة المجانية لا تضمن أن Vercel وFirebase يظلان مجانيين لكل الميزات أو حجم الاستخدام. تختلف الحصص ومتطلبات خطة Firebase حسب المشروع والمنطقة/الميزات، وقد يتطلب Cloud Storage أو تجاوز حدود الاستخدام تفعيل فوترة؛ كما قد تحد Vercel Hobby من مدة/تزامن الوظائف. راجع حدود الخطط الحالية قبل ربط مستخدمين فعليين، واستخدم مشروع Firebase منفصل للتطوير، وضع ميزانيات وتنبيهات حيثما توفرت. لا تتضمن هذه الشيفرة ضماناً بأن الخدمة الكاملة ستعمل بلا رسوم.

## نطاق التنفيذ

- بوابات الطالب وولي الأمر والمعلم الواحد والإدارة والمشرف، مع توجيه دخول الإدارة عبر بوابة ولي الأمر والمشرف عبر مسار الطالب.
- مادة واحدة ومعلم واحد؛ لا توجد أدوات لإدارة عدة معلمين/مواد.
- صفحة دخول عامة بمحتوى الأوائل (بعد الموافقة)، الكتب والدورات، وروابط عامة؛ حالات الفراغ حقيقية وليست بيانات عرض.
- إدارة صفوف/فصول ومحتوى وواجبات، تحكم الشعار والألوان والثيم وأقسام الدخول وروابط التواصل.
- طلبات دفع يدوي بمراجعة المعلم، ورموز تفعيل للدورات تصدر من المعلم وتسترد مرة واحدة بمعاملة Firestore.
- لون فاتح/داكن محفوظ للمستخدم، ورابط واتساب عائم مستقل دائماً عن CRUD الروابط.

## التحقق

من جذر المشروع شغّل `npm.cmd run build:all` للتحقق من API والواجهة. يتطلب اختبار التكامل الفعلي إعداد مشروع Firebase وVercel والاعتمادات السرية؛ لم تُنشأ موارد أو تُنشر نسخة من هذه المساحة.
